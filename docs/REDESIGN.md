# 数感探索乐园 — 重新设计方案

## 一、核心问题诊断

当前版本体验不理想的主要原因：

| 问题 | 现状 | 应改为 |
|:---|:---|:---|
| 答错惩罚 | 扣生命值，3次机会用完就失败 | **无惩罚机制**，答错只是换个方式再试 |
| 文字过多 | 题目用文字描述 | **纯图形化**，用物品数量代替文字 |
| 交互单一 | 主要是点按钮选择 | **拖拽为主**，符合儿童天性 |
| 反馈不足 | 简单emoji弹窗 | **多感官反馈**：动画+音效+角色反应 |
| 难度跳跃 | 每关难度固定 | **自适应难度**，根据正确率动态调整 |
| 缺乏引导 | 直接出题 | **故事化引导**，跳跳带队冒险 |

## 二、设计规范（来自行业研究）

### 2.1 儿童UI设计原则

```
来源：Khan Academy Kids / 火花思维 / 斑马思维 / PBS Kids

1. 视觉优先
   - 文字≤10个字/屏
   - 用图标和动画代替文字说明
   - 颜色≤3种主色（马卡龙低饱和）

2. 大按钮
   - 点击区域≥80×80px
   - 按钮间距≥12px
   - 放在屏幕下半部分（拇指热区）

3. 容错设计
   - 答错不扣分、不惩罚
   - 错误选项轻柔弹回，不消失
   - 用鼓励语言代替"错误"：再想想哦→换个方式试试

4. 即时反馈
   - 0.5秒内响应
   - 正确：烟花/星星/角色欢呼
   - 错误：温和摇头/轻声鼓励

5. 角色陪伴
   - 一个固定角色全程引导
   - 角色有表情变化（开心/思考/加油）
   - 用角色说话代替系统文字
```

### 2.2 护眼规范

```
来源：萌芽学前 / 儿童视听训练小程序

1. 每20分钟强制休息20秒
2. 屏幕亮度≤70%时提醒
3. 背景色用暖色（#FFF8E7），不用纯白
4. 避免闪烁动画
5. 每次使用≤30分钟
```

### 2.3 游戏化设计

```
来源：小蜗大作战 / 儿童教育小程序

1. 低门槛高天花板
   - 前3关极简单（100%正确率）
   - 难度渐进，每3关+1档

2. 奖励机制
   - 星星/贴纸/角色皮肤
   - 可视化收集册
   - 不搞排行榜（避免焦虑）

3. 进度可视化
   - 地图式关卡
   - 已完成/当前/锁定状态清晰
   - 每关显示获得的星星
```

## 三、新架构设计

### 3.1 页面结构

```
pages/
├── splash/          # 启动页（跳跳动画）
├── home/            # 主页（5个模块卡片）
├── adventure/       # 冒险地图（关卡路径）
├── game/            # 游戏核心页
├── result/          # 结算页
├── collection/      # 贴纸收集册
└── settings/        # 家长设置（护眼/音效）

components/
├── FrogCharacter    # 跳跳角色（表情系统）
├── StarRating       # 星级评价
├── ScatterItems     # 散落物品
├── TenFrame         # 十格框
├── NumberHouse      # 数字房子
├── RiverCrossing    # 过河动画
├── ShoppingCart     # 购物车
└── EyeRest          # 护眼提醒
```

### 3.2 核心交互方式

```
模块一：感知数量
├── 点击数数（点一个数一个）
├── 滑动估数（滑块选择范围）
└── 拖拽排列（从小到大排列）

模块二：十进制
├── 拖拽装盒（满10自动扎捆）
├── 拖拽拆分（把10拆成两部分）
└── 拖拽堆塔（10个小积木换1个大的）

模块三：位值
├── 拖拽进房间（数字进个位/十位）
├── 拖拽配对（积木↔数字）
└── 拖拽拆解（把数字拆开）

模块四：进退位
├── 拖拽过河（青蛙过桥合并）
├── 拖拽拿走（从一堆里拿走几个）
└── 拖拽补位（不够就拆一捆）

模块五：购物
├── 拖拽付款（把钱拖到商品上）
├── 拖拽找零（从收银台拖出零钱）
└── 拖拽采购（商品拖进购物车）
```

## 四、技术方案

### 4.1 技术栈

```
框架：微信小游戏（Canvas 2D）
  - 性能好，拖拽流畅
  - 原生触摸事件支持

动画：CSS动画 + requestAnimationFrame
  - 弹性动画（spring physics）
  - 粒子效果（答对时撒花）

音效：Web Audio API
  - 夸张鼓励风格
  - 连击音效递进

存储：localStorage + 云开发
  - 本地：进度、设置、贴纸
  - 云端：题库（后续）
```

## 五、UI设计规范

### 5.1 配色方案

```
主色：#FF9B50（温暖橙）
辅色：#4ECDC4（清新绿）
强调：#FF6B6B（柔和红）
成功：#51CF66（活力绿）
背景：#FFF8E7（暖白）
文字：#495057（深灰）

禁止使用：
❌ 纯白 #FFFFFF（太刺眼）
❌ 纯黑 #000000（太沉重）
❌ 高饱和红（代表错误，儿童会焦虑）
```

### 5.2 按钮规范

```
尺寸：最小80×80px
圆角：20px（圆润友好）
间距：≥12px
颜色：默认白色+边框，按下变色
字体：≥18px，加粗
位置：屏幕下半部分
```

### 5.3 反馈规范

```
答对：
  ✅ 绿色边框 + 放大动画
  ✅ 烟花/星星粒子效果
  ✅ 跳跳举手欢呼
  ✅ 夸张上升音效
  ✅ 鼓励文字（随机）

答错：
  ❌ 不扣分、不显示红叉
  ✅ 选项轻柔弹回
  ✅ 跳跳温和摇头
  ✅ 柔和音效
  ✅ 鼓励文字："再想想哦~"
  ✅ 3秒后自动显示正确答案
```
